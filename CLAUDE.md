# Manners -- guide for agents

Read this first. Not shipped (`.pkgmeta` ignores it). State and open items:
`STATUS.md`. Release checklist: `RELEASING.md`. What changed: `CHANGELOG.md`
(written for players). Test internals: `tests/README.md`. Tool details:
`tools/README.md`.

## What it is

A World of Warcraft addon (MIT, github.com/fpsacha/Manners, branch `master`,
CurseForge 1705364, Wago `rNkgzlNa`) that returns buffs. It notices who buffed
you, works out what you owe, and puts one secure button (the prompt) on screen;
a press targets them by name, casts, and hands your target back. It also offers
your group, people who ask in chat, and passers-by missing your buff, reminds
you of your own self-buffs, keeps a favour ledger, and can say a line when it
casts (fixed sets or the "In character" set). Since 1.11.25 the same button
also offers a resurrection, a cure, a courtesy somebody asked for and a polite
ask for a buff you lack ("Entry kinds" below). Addons cannot cast on their own:
everything except the keypress is decided in Lua and parked on the button.

## File map

Load order is `Manners.toc`'s file list; every test loader reads it from there
(`tests/addonfiles.lua`). A new file goes into `Manners.toc`, then
`python tools/maketocs.py` rewrites the five generated tocs, which carry the
same list (`tests/validate.py` fails until they match).

Cross-file sharing: a local one file needs from another goes on `ns` where it
is defined; a later file copies it into a local at load, an earlier one (Core's
lifecycle) reads `ns.X` at call time.

Adding a setting: its default in `Core.lua`'s `defaults` (and repair in
`ns.ClampSettings`), its definition in `Options/<Tab>.lua`, its place in
`Options/Window/Layout.lua` (`tests/scenarios/layout.lua` requires every
control placed exactly once), and its strings translated. A setting most
players of a class change also goes in the layout's `simple` list, or the
simple view leaves it out; one that belongs to a switch is indented under it
and named in `parents`, so search can say which switch to turn on. No page
is over about three screens with its folds shut (`menu.lua` holds each to
3.1): fold fine print rather than raise that.

- **Flavour.lua** matches the interface number against bands tried in order
  (camelot first: 16001 and 11509 are both five digits). `WOW_PROJECT_ID` is a
  cross-check only (MAINLINE on retail and on Forever's early builds), except
  Forever's own `WOW_PROJECT_CAMELOT` (18 in its 1.60.1.70532 source), which
  names one client and wins where the interface number has no band or
  another client's (`tests/scenarios/flavour-project.lua`). An unknown
  interface falls back to the project id's family, else `modern`.
- **Buffs.lua** has one set per flavour (`SETS`); an unrecognised flavour gets
  its family's (classic -> vanilla, modern -> mainline). The chosen set fills
  `ns.BUFFS`, `ns.OWN_BUFFS`, `ns.EXCLUSIVE_BUFFS`, `ns.CLASS_AUTO`,
  `ns.CLASSES_WITHOUT_BUFFS`, `ns.PARTY_IS_SUBGROUP`, `ns.GROUP_IS_RAID`,
  `ns.SHOUT_YARDS`, `ns.WIDE_CASTS`, `ns.GROUP_BY_CLASS`, `ns.FAVOUR_ONLY_IDS`,
  `ns.NOT_FAVOUR_IDS`, `ns.RANK_LEVEL`, `ns.STAT_VALUE`, `ns.STAT_TIERS`,
  `ns.LEVEL_GATED`. Branch on those fields
  and the per-buff flags (`partyOnly`, `groupOnly`, `selfCast`, `alone`, `alike`,
  `blockers`, `neverAuto`, `optIn`, `returnOnly`, ... documented at the top of
  the file) rather than on
  flavour names. `blockers` and `ns.STAT_VALUE` are the flat-stat scrolls that
  hold a weaker rank of Arcane Intellect, Fortitude or Divine Spirit off
  (Classic Era, TBC, Forever; Mists and retail give percentages and have none),
  weighed numerically in `UnitHasBuff`; `tools/audit_ids.py` holds them to
  SpellEffect. On Forever the blockers also hold the camping buffs Boosted
  Stamina, Intellect and Spirit, whose worth goes by the wearer's level
  (`ns.STAT_TIERS`, `ns.CampWorth`: the aura's own points, else the tier the
  feature's text gives; the audit holds both). `ns.LEVEL_GATED` (the vanilla
  set's `levelGated`, read by Forever's and Burning Crusade's) says a cast
  lands only within ten levels of its rank: a buff's `lowLevel`, worked out in
  the lookups, keeps it off anybody too low for every rank (`Castable`), and
  `ns.RANK_LEVEL` holds the group versions' levels too, for the fold
  (GroupBuffs.lua, `TooLow`) and for a group version worn (`UnitHasBuff`). The
  camelot set is vanilla's (`__index`) with its own buffs, and is still called
  "vanilla" in `ns.BUFFS_SOURCE`; tbc builds on vanilla the same way.
- **How long each buff lasts** is a table of ids per client in `Buffs.lua`
  ("how long each lasts", `ns.SPELL_SECONDS`: seconds, 0 no timer, absent
  unknown), from each client's SpellDuration; `tools/audit_ids.py` holds every
  row to it, so a new id in a set needs its row. A top-up's lead is worked out
  from it in `Core.lua` (`ns.TopUpLead`, `ns.LeadFor`: a tenth of the length,
  the slider `refreshUnder` its ceiling, `refreshRaid` times in a raid or
  dungeon, your own buffs half as much again, passers-by the last half
  minute); the aura's own `duration` beats the table.
- **Who is offered first** (Queue.lua, `PRIORITY` and `OfferRank`): by tier
  (target, a ready check or a death, owed, asked, yourself, group, passers-by),
  then range, then inside a tier what is missing before what nobody could read
  before a top-up, then the buff's place in the walk (everybody's first
  missing buff before anybody's second; no place for a class whose buffs
  replace one another), then group cast, friends, name. `Prompt:PickTop` keeps
  the current person on a tie only while no worse by that order, and the
  fight's rota steps through the queue as built.
- **A blessing for each class** (`buff.forClass`, CLASS -> buff key; Who to
  buff, under the buff order: `who.classNote`, `classPick`, `classBlessing`,
  `classReset`, for a class whose buffs replace one another): the blessing
  chosen for somebody's class goes to the head of the walk in `PickBuffFor`'s
  exclusive branch (`opts.theirClass`, read by the queue only while a class
  has one) and nothing else changes; never over a pin.
- **Unasked, by default**: `optIn` buffs are off until ticked (Detect
  Invisibility for the group; Shadow Protection on Classic Era, Forever and
  TBC), and Detect Invisibility stays the group's alone (`membersOnly`) until
  *Offer Detect Invisibility to passers-by too* under it is ticked
  (`buff.detectPassers`, off; `ns.PassersToo`, asked by `Castable`,
  `ns.OnlyReachesGroup` and the buff's label); a `returnOnly` buff (Unending Breath there) goes only to a favour's
  giver (`opts.owed`) and to a request by name (`opts.asked`, which a plain
  "buff pls" is not); `buff.skipCasters` is on.

`--jobs N` on check.py, prove.py, fuzz.py, runscenarios.py and selftest.py
defaults to `tools/jobs.py`'s number: the cores less two, fewer when free
memory is short (0.75 GB a job), and never more than `MANNERS_JOBS` when that
is set (`python tools/jobs.py` prints it and why). Set `MANNERS_JOBS=6` once
while other agents share the machine rather than `--jobs` on every command.
While building, prove each new mutation with `tools/prove.py`; before handing
work back, `check.py --lint --flavours --anchors` and `selftest.py --changed`;
the full selftest runs on GitHub (`selftest.yml`) and the release tool reads
it. Before a release, `check.py --release` and `RELEASE-CHECK.md` (five
minutes in the game, by the author).

`tests/runscenarios.py` flags: `--scenario NAME` and `--file FILE`
(`scenarios.lua` or a file in `tests/scenarios/`; both repeatable),
`--select pick.json`, `--jobs N`, `--flavour X` (the whole suite with X as
`Mock.reset()`'s client; same as `MANNERS_MOCK_FLAVOUR=X`), `--flavour X
--baseline` (prints only failures not in `tests/baselines/<X>.txt`, and
baseline entries that now pass; `--update-baseline` rewrites the file),
`--trace PATH` and `--shard I/K` (used by selftest). A run ends with
`failures: N`. Off Forever most reds are fixtures written for Forever (two-part
names, scrolls, secrets), which is what the baselines hold.

`tests/selftest.py` flags: `--anchors` (every mutation still finds its text),
`--changed [REF]`, `--only TEXT`, `--plan` (which scenarios judge each
mutation), `--whole` (every mutation on the whole suite, slow), `--fresh-trace`
(ignore the trace kept in `%TEMP%/manners-selftest-trace`, and trace even
where the fast proof would do), `--jobs N`. A run fails on MISSED, WRONG
CHECK, ANCHOR GONE or NOT RESTORED. A narrowed run that keeps no mutation
ends at once.

Others: `tests/baseline.py` (a fingerprint of what Forever decides and arms:
diff it before and after a change made for another client), `tests/bughunt.py`
(known fault shapes; reports known false positives), `tools/lua51_limits.py`
(the tightest functions), `tools/perf_probe.py` and `tools/profile_scan.py`
(pcall counts, cost per scan), `tools/render_prompt.py`, `render_ledger.py`,
`render_options.py` (draw the UI from the mock; not pixel-true about light),
`tools/audit_look_contrast.py` (every look's words measured on the pictures:
4.5:1 for each line, `--check`; run it after any change to a look).

CI (`ci.yml`, every push): validate, runharness, `selftest.py --anchors`,
runscenarios (`--jobs 4`), and the listing images drawn with `--strict`.
`release.yml` runs only validate, runharness and `--anchors` before packaging:
`tools/release.py` tags only content CI passed. The full
selftest is `selftest.yml`: sixteen runners, one `--part I/16` each, nightly, on
every push to master and on `gh workflow run selftest.yml`; `gh workflow run
selftest.yml --ref <branch>` proves a branch before it is merged, and the
release tool counts that run once the branch is in master. A mutation the
pieces of the suite judged is remembered by the piece that caught it
(`catches.json` beside the kept trace) and tried there first next time.

Nothing here talks to a running client. For the game itself, ask the user to
run `/manners selftest launch` (a report to paste) or the `/manners dev` tools
(`clicks`, `try`, `look`, `forms`) and paste the output, or for a screenshot.

## Dev tools

Quick helpers for working in a worktree (`tools/README.md` has the details):

- `python tools/lint.py [FILE ...]`: Lua 5.1 syntax of every file the toc loads
  plus `tests/*.lua`, `tests/scenarios/*.lua` and `tools/*.lua`, every `.py`
  under `tools/` and `tests/` compiled, and the generated tocs current. One
  `file:line: what` per problem, exit 1. Under a second. It does not count
  upvalues or locals: `tests/validate.py` does. `--quick` is the hook's form.
- `python tools/anchors_for.py FILE[:LINE[-LINE]|:FUNCTION]` **before** editing
  a line: the mutations whose `old` text sits there (within 3 lines, `--near N`),
  each with its label, its `expect` and the file:line of its `mutate()` call.
  `python tools/anchors_for.py --check-after` **after**: only the mutations that
  no longer find their text (`selftest.py --anchors`, gone ones only; exit 1
  too when a mutation file does not run). Re-aim them in the same change,
  never delete them.
- `python tools/clients_watch.py`: each client's interface number and build in
  the repo against `Gethe/wow-ui-source` (`version.txt` per branch) and
  `Ketho/BlizzardInterfaceResources`, plus the PTR and beta branches. Exit 1 on
  drift (a toc that would show out of date to players on that client) or when
  the repo's own sources disagree; 2 when upstream cannot be read. Needs `gh`.
- `python tools/prove.py "<label text>" [...]` or `--file
  tests/mutations/<topic>.py` (`--list` says what would run): a new mutation
  proven in seconds, on its topic's scenario file and the files that hold its
  `expect`. This is what to run after writing a scenario and its mutation,
  not `selftest.py --only`. MISSED there means "not in those files": a check
  that lives elsewhere (a control's place in `layout.lua`) needs its scenario
  named in `expect`, or `selftest.py --only` to find it.
- `python tools/check.py --lint --flavours --anchors`: lint first, then the
  rest; a lint failure stops it before anything else runs. `--release` is the
  same and the locales, the looks' previews and contrast, bughunt and the
  quick fuzzer: the one command before a release.
- `python tools/jobs.py`: how many processes the tools run at once by default
  and why; `MANNERS_JOBS=N` caps them all.
- `.claude/settings.json` allows the commands above, `python tools/*`,
  `python tests/*`, the everyday git (`git branch` only to list) and `gh run`
  commands and `gh api` reads of the two upstream repos (every flag that makes it
  a write is denied); it asks before `tools/release.py` and `tests/setversion.py`,
  and denies force pushes, `git reset --hard`, `git clean`, forced or `-D`
  branch changes, `rm -rf` and `gh secret`. A PostToolUse hook runs
  `tools/lint.py --quick` (from `$CLAUDE_PROJECT_DIR`, so a `cd` does not break
  it) after every Edit or Write: it is silent when the file compiles and prints
  the problem (exit 2) when it does not. Slash commands in `.claude/commands/`:
  `/check`, `/release`, `/bughunt`, `/translate`, `/phrases`.
- `python tools/perf_probe.py [--flavour X] [--compare before.json]`: pcalls,
  client calls and allocations per scan in idle, city, dungeon, raid, raidgc
  and citynever, as any of the five clients. Measure before and after a change
  to a hot path; `python tests/baseline.py` (what Forever decides and arms) must
  stay identical across a performance change. `tools/profile_scan.py` is
  Forever-only (its fixtures use two-part names).
- Audits (each documents itself with `-h`; none is part of `check.py`; they
  download client data into a cache outside the repo): `tools/audit_ids.py
  [--client X] [--notes]` holds every spell, item, aura, race and class id the
  addon has to that build's wago.tools tables (run it after any change to
  `Buffs.lua`); `tools/audit_groups.py` the group casts; `tools/audit_api.py`
  every client API, event, CVar and widget method the addon uses against each
  client's own API, saying which uses are guarded and which would throw (run it
  before adding an API call, or when a toc moves to a new build; `audit_apis.py`
  is the lighter version with `--textures`, `--globals` and `--ptr`, and
  `audit_docs.py` reads Blizzard's own API documentation for what is secret or
  restricted); `tools/migration_check.py` loads every release tag's addon on the
  mock, saves its settings and loads them in the current addon (a setting a past
  release saved that the current one mangles is a finding);
  `tools/audit_saved_boxes.py` and `tools/legacy_lines.py` the In character
  phrase box across releases and languages; `tools/audit_i18n_*.py` lead lists
  for translators (formats, widths, gender, terms, references).
- `python tools/fuzz.py --quick --jobs 2`: a seeded random game (rosters, auras,
  deaths, fights, chat, presses, withheld values, settings, reloads) played on
  every client with invariants checked after each step: 24 seeds x 5 clients x
  100 steps, about 30 s. `--seeds N [--flavour X] [--steps M]` for more (500
  seeds on every client is about 13 minutes with `--jobs 2`); a failure prints
  `flavour=X seed=S`, replay it with `--flavour X --seed S [--trace]`, shrink it
  with `--minimize`, which prints a quoted `--play '<steps>'` line. 10,000 runs
  of 200 steps found no addon fault at 1.7.4 beyond one the reviewer caught; run
  it after any change to the queue, the aura or event handlers, or the macro.
- Edit nothing under `tests/` or the addon while `check.py` or `selftest.py`
  runs: each scenario process keeps a compiled copy of every file, and a change
  mid-run fails the step with "changed during the run" while still printing
  `failures: 0`. The selftest trace is keyed on the tests (and on `--jobs`);
  after a test edit `--changed` and `--only` no longer trace first: they try
  each mutation on its own scenario files and trace only for what that leaves.

## Scenarios and mutations

- **Scenarios** are Lua run against the mock. `tests/scenarios.lua` is the old
  main file (do not append to it); new ones go in `tests/scenarios/<topic>.lua`,
  found by glob and run after the main file in name order. A file starts
  `local dir, H = ...` and takes helpers from `H` (`fail`, `load`, `drive`,
  `strangers`, `freshPrompt`, `pressButton`, `owe`, ...: the table near the end
  of `scenarios.lua`). Shape: `Mock.reset()`, set the mock
  (`Mock.setFlavour("mists")`, `Mock.class = "PRIEST"`, ...),
  `local ns = load(scenario)`; `nil` means "skip" (a narrowed run left it out);
  report with `fail(scenario, text)`. Put back every global you replace.
- **Names** start with the file's topic (`"flows-fix: vanilla: ..."`,
  `"era: ..."`) so a mutation can name exactly one.
- **Mutations** live in `tests/mutations/<topic>.py`, found by glob and run with
  `mutate()` in scope:
  `mutate(file, old, new, label, expect=..., script="runscenarios.py")`.
  `old` is exact code text (first occurrence is replaced; make it unique),
  `expect` is matched case-insensitively against the failing lines (usually a
  scenario name), `script` is the suite that must catch it (default
  `runharness.py`; `validate.py` for doc and structure checks). Every fix gets
  a scenario and a mutation that undoes the fix.
- **Anchors**: changing code or comments a mutation's `old` sits on means
  updating that mutation so it still applies the same fault;
  `python tests/selftest.py --anchors` must report every anchor live.
  `python tools/anchors_for.py FILE:LINE` lists them before the edit and
  `--check-after` only the gone ones after it ("Dev tools" above).
- **Anchors outside the code**: mutations also sit on `README.md`,
  `RELEASING.md`, `CHANGELOG.md`, `Manners.toc` and both workflows
  (`ci.yml`, `release.yml`), mostly judged by validate.py. One README anchor,
  in the player text about the wrong Mort, is judged by runscenarios.py: a
  scenario in `scenarios.lua` reads `README.md` and fails when the README
  promises more than the code does. Rewording any of these files means
  running `--anchors` too.
- A scenario that cannot go red is worse than none: run the mutation and see it
  CAUGHT by the named check. `python tools/prove.py "<label text>"` does that
  in seconds (`--file tests/mutations/<topic>.py` for a whole file, `--jobs N`):
  the topic's scenario file and every scenario file holding the `expect`,
  green on the clean tree first, then with the mutation in a throwaway copy.
  CAUGHT is the proof; MISSED means "not in those files" (name the scenario
  in `expect`), WRONG CHECK that another check failed and the named one did
  not, RED BEFORE that the scenario file is red without the mutation. A
  mutation re-aimed after an edit is proven again the same way.
- **Timers.** A scenario that reads `Mock.timers` shares the clock with
  everything the login parks on it (the reminder to set a key, twenty seconds
  in; the line said once in town, twelve): take those off first
  (`ns.KeyNudge = nil`, as `hunt24-favours.lua` does) or look for your own
  timer by what it does, not by its place in the list.
- **Nothing on `ns` for the tests alone.** `tests/validate.py` fails a symbol
  put on `ns` that only `tests/scenarios/*.lua` read ("WRITE-ONLY"): a
  scenario sees a module's memory by what the addon then does (the queue, the
  macro, a line of `/manners debug`), not through a table exposed for it.

## Release

1. Documentation first, in the same change as the code: notes under
   `## Unreleased` at the top of `CHANGELOG.md`, for players, with the date in
   italics on a line of its own under the heading, `### Highlights` first
   (the few things that matter most, a line or two each) and `### Fixes` last,
   then `python tools/make_whatsnew.py`; the README's
   player sections for every new or changed setting; `STATUS.md` (version,
   open items, what only the live game can say); the three listing files in
   `.github/` where a feature is new; this file, `tools/README.md` and
   `tests/README.md` where a file, tool or rule changed.
2. The full selftest is `selftest.yml` on GitHub; `release.py` reads its last
   green run of master and runs only the mutations changed since. Nothing by
   hand unless GitHub cannot run it (then the full run and `--skip-selftest`).
3. `python tools/release.py X.Y.Z` (`--dry-run` prints the steps). It checks
   master, a clean tree, the notes and `tools/check.py`; runs
   `tests/setversion.py`; commits "Manners X.Y.Z" with the Co-Authored-By line
   from `--coauthor` or `MANNERS_COAUTHOR`; pushes master and waits for CI;
   tags `vX.Y.Z` (annotated) and pushes it; waits for `release.yml`; prints
   the packager's "Game version:" line and the upload results.

Versions: `X.Y.Z`, `X.Y.Z-alpha.N`, `X.Y.Z-beta.N` only. Never edit a version
by hand: `tests/setversion.py` writes every toc, `ns.BUILD` in
`Prompt/Prompt.lua` and the changelog heading. The manual steps, and how to take
back a failed tag, are in `RELEASING.md`.

## Translations

Every player-facing string is `L["English text"]`, a literal (validate fails on
`L[variable]`). The key is the English; changing the English is a new key.
Validate fails on any locale missing a key or holding one the code no longer
asks for, so no new or changed string lands without all eight translations
(deDE esES frFR itIT koKR ptBR zhCN zhTW). No Russian, ever.

1. `python tools/locale_todo.py [--out DIR]`: `<code>.todo.json` per locale,
   each missing key mapped to `""`, and the counts.
2. Translate the values. Keep every `%s`, `{token}` and `|c...|r` as the English
   has them. Game terms -- spell, item, class, race and zone names, and the
   client's own UI words (nameplates, Key Bindings) -- use that client's
   official localized name (Wowhead in that language; GlobalStrings from
   Ketho/BlizzardInterfaceResources), never a free translation. Slash
   commands stay English.
3. `python tools/locale_add.py <code> <file.json> [...]` per locale: merges
   into `Locales/<code>.lua` without losing a line, checks with
   `tools/check_translation.py`, rebuilds with `tools/build_locale.py`.
4. `python tests/validate.py`.

The addon's own words, the same in every string: "passer-by" (never "nearby")
for somebody near you who is not in your group; "buff back" and *Buffing back*
for returning a favour; *Favour ledger* stays the ledger's name. A retired
string is removed from every locale by hand before `locale_add.py`, which
refuses to drop a line.

The options window's layout (`Options/Window/Layout.lua`, documented in its
header) has, since round 37: `buttons` (a run of buttons left to right),
`match` (two fields of one width), `offNotes` (path -> why a greyed row is
greyed, drawn by `W.OffNote`), `keywords` (search words) and `parents` (a
hidden control found by search, with the switch to turn on first: only while
that switch is off, and only where `parentsIf`, path -> function, does not
say the switch would show nothing, as for a courtesy another class has). A
fold marked `plain = true` holds no setting and gets no fine-print caption
over it (the hall of fame). A page of more than three titled sections
names its sub-divisions in `subpages` (lists of its section keys, seven at
most, an optional `title`; `tests/scenarios/subpages.lua` holds the shape):
a section named in none (the line a page opens with) is drawn with each. They live
in the layout, not the AceConfig definition, which rejects unknown keys.

`python tools/locale_keys.py --missing <code>` lists the gaps of one locale.

## In character phrases

`Phrases.lua` holds the pools; `RP.Pick` chooses one line at the click from the
pools that fit the moment. Pools: `RP.RACE.<family>.<kind>` (kinds `thanks`,
`asked`, `offer`, `group`, `kin`, and `night`/`morning`/`city`/`outsider`
where a people has them), `RP.FACTION`, `RP.GENERAL`, `RP.KIN`,
`RP.CLASS.<CLASS>.<kind>`, `RP.SPELL.<buff key>`, `RP.GIFT.<buff key>` (thanks
only; `{gift}` is the spell they gave you), `RP.TRADE`, `RP.HISTORY`,
`RP.PLACE`, `RP.TIME`, `RP.TARGET`, `RP.SAME.<CLASS>`, `RP.ONTO`.
`<family>` comes from `RP.FAMILY`, keyed by `UnitRace`'s second return.

- Add lines with `python tools/add_phrases.py pools.json`: a list of
  `{"pool": "RACE.<family>.<kind>" | "CLASS.<CLASS>.<kind>" | "SPELL.<key>" |
  "GIFT.<key>" | "SAME.<CLASS>", "lines": [...]}`. It appends to the pool (or
  creates it at the end of its table), escapes, and refuses what
  `tests/scenarios/rp.lua` would.
- The rules (`rp: the lines are short and safe in a macro`): at most 85
  bytes (UTF-8: an accented letter or a curly apostrophe counts 2 or 3) with
  `{name}` -> "Bartholomewz" and `{buff}`/`{gift}` ->
  "Power Word: Fortitude"; no `|`, `[`, `]` or line break, no leading `/`; no
  line equal to another once reduced to its letters; only the `{name}`,
  `{buff}`, `{gift}` tokens, `{gift}` only in TRADE and GIFT; never the word
  "buff" (the set is in character). A buff key only another client has goes
  in `rp.lua`'s `elsewhere` list.
- Pool sizes (`rp: every moment the set knows has lines`): at least
  `RP.SPREAD` (three) lines in every race kind, FACTION, GENERAL, CLASS kind,
  SPELL, SAME, TRADE, HISTORY, PLACE, TIME and TARGET pool; two in a GIFT
  pool, a people's `outsider` pools and an ONTO pool. A new pool below that
  turns `rp.lua` red, and `add_phrases.py` refuses it.
- Each line is a player-facing string: all eight translations before it lands.
  On other languages an untranslated line is dropped at load.
- **Examples caveat**: the first lines of the pools are the phrase box's
  examples, and a player's saved box is recognised by matching them exactly.
  Never reword or reorder the first lines of a pool; append. A reworded
  example goes into `RP.LEGACY.reworded` as it read before. Giving a people
  its first pool changes its examples (as for the Haranir in 1.7.2). The same
  holds for TRANSLATIONS: rewording a translation of one of a pool's first lines
  in `Locales/<code>.lua` makes every box saved before it read as the player's
  own, and In character stops for that player (1.6.6's 750 translation fixes did
  this until 1.7.6). The earlier translations are kept in `RP.LEGACY_TRANSLATED`
  (`tools/legacy_lines.py` builds and checks it): record the old text there
  whenever such a translation changes. `python tools/audit_saved_boxes.py` saves
  a box with every released tag in every language and checks the current
  addon still recognises it (its tag list is read from the repository's own
  tags). A box filled in one language and opened by a client in another is
  recognised through `RP.OTHER_KEYS` and `RP.OTHER_HASH` in `Phrases.lua`, every
  set and example line in every language by the hash of its text (the locale
  files load one per client, so the other languages' text is not there to ask):
  after any change to a set, an example or a translation of one, run `python
  tools/legacy_lines.py --write-other` (`--check-other` says whether it is
  current; `--check` runs it too), and `python tools/audit_saved_boxes.py --tags
  HEAD --saved-as deDE` (any language) reads the current boxes on every client.
- Race file names are the client's `ChrRaces.ClientFileString`, not the race's
  name: `Scourge` (Forsaken), `EarthenDwarf`, `Harronir` (the Haranir). 1.7.2's
  Haranir lines never played because the key was guessed. Look it up.

## Hard rules

- **Lua 5.1.** 60 upvalues per function, 200 active locals. `tests/validate.py`
  fails a function over 55 upvalues or 190 active locals, or a file whose main
  chunk keeps fewer than 10 locals free. Fix by putting helpers in a
  `do ... end` block or lifting closures to file level. Tests run on
  `lupa.lua51`; test Lua stays 5.1-clean too.
- **Secret values.** Anything branched on passes through `ns.plain()` (secret ->
  nil). No `pcall`/`ns.safecall` on busy paths (per unit, per event, per
  repaint): call directly after a `type()` check. `pcall` only for restricted
  aura reads, library code, calls handed a possibly secret value, API drift
  and setup; `ns.Guard` at event, timer and module boundaries. The policy is at
  the top of `Core.lua`'s secret-safe section; `tests/scenarios/perf-budget.lua`
  caps pcalls, client calls and KB per scan for each of the five clients in six
  places (idle, city, dungeon, raid, city with a never-offer list, raid with
  group casts), at about measured + 25%; `MANNERS_PERF_REPORT=1 python
  tests/runscenarios.py --file perf-budget.lua` prints what each measures
  (Forever: idle 10, city 13, raid 18 pcalls). No file keeps its own copy of
  `pcall`.
- **Combat.** The secure button's attributes cannot change in combat: what is
  on the prompt when a fight starts stays until it ends. The one exception is
  secure code: with *Hide the prompt in combat* on, `Prompt/Fight.lua`'s
  snippet takes the macro off the prompt and its rows and only then hides the
  prompt, and only when the pull (`PLAYER_REGEN_DISABLED`, before the
  lockdown) has left the bar macro holding no cast (`ns.BarMacroDisarmed`).
  The other is the fight's rota (`Prompt/Fight.lua`, `prompt.fightRota`, on):
  at the pull the header is handed the macro of everybody in the queue, and a
  `SecureHandlerWrapScript` round the prompt's OnClick writes the next one on
  the button at every left press, so a fight's presses go round the people it
  began with rather than at one of them; `SyncFightRota`, from the prompt's
  PostClick, then points `S.current` at whoever the button now casts at. Lua
  still writes nothing on the button in a fight.
  Never hide the prompt by any route that leaves it, a row or the bar macro
  able to cast: a hidden secure button still fires from its binding and
  `/click`. The snippet writes nothing back; the repaint after the fight arms
  the prompt afresh.
- **Secure frames never anchor to a region.** The client refuses a protected
  frame's `SetPoint` onto a font string or texture ("Cannot anchor protected
  frames to regions"); 1.8.0 did it for the list's names and threw in
  ApplyStyle at every login. Anchor secure buttons to frames (the prompt's
  art, its button); `tests/mockwidgets.lua` refuses the region anchor as the
  client does.
- **Macro.** 255 characters (`ns.MACRO_LIMIT`); the spoken line gets what the
  cast lines leave (`ns.PhraseBudget`). A press on anybody, yourself included,
  is `/target <name>`, `/cast <spell>`, and `/targetlasttarget` when your
  target is handed back (`Prompt/Macro.lua`, `STRATEGIES`); a self-cast shout
  is a bare `/cast`, a scroll `/use item:<id>`, and a scroll that needs a
  friendly target (Classic's stat scrolls, `STRATEGIES.allyscroll`) `/target
  <your name>`, `/use item:<id>` and the hand-back. No `[@player]` or any
  `[@unit]` conditional: they do not resolve on Forever. Secure buttons
  register `"AnyDown"`. Only the left mouse button casts: every other button
  (type2..type5 and the wildcards `*type2`..`*type31`) is set to `none` in
  `Prompt/Macro.lua` `SilenceOtherButtons`, because the client looks an
  attribute up modifier-prefixed first and shift-right-click would otherwise
  run the macro. No macro ever /clicks the prompt: the client refuses a macro
  that clicks a button which runs a macro (Blizzard, WoWUIBugs #552; Classic
  Era 1.15.9 cast nothing from `/click MannersPrompt LeftButton 1`). The bar
  macro carries the cast under `/click MannersBar` (Clicks.lua, click macro):
  the prompt's macro, spoken line included when one is armed and fits beside
  the bar line (the arming's own judgement: a bar press has no PreClick to
  hold it at the last moment, so one said over a cast that then fails cannot be
  taken back; a line too long for the bar's copy leaves it the cast alone),
  written out of combat only, never during a bar press or with the macro
  window open, only into the macro named Manners while its body is Manners'
  own (the bar line first, then a shape Manners writes: at most one `/target
  <name>`, one `/cast <spell>` with at most one spoken line after it, in a
  channel of `ns.CHANNEL_COMMANDS` and with no `[`, or `/use item:<id>` with at
  most one `/use 16|17` (after a `/target` of your own name for a scroll), and
  after a `/target` at most one hand-back, in that order; `#` lines kept on
  top; Clicks.lua `Shaped`).
  The press is filed by Press.lua's OnBarClick against `Prompt.bar`, and only
  when the macro running (`GetRunningMacro`) is the Manners one; a body a
  session before left, found in a fight, is read (`Look` runs in combat,
  writing nothing) and its presses said and never filed (`StaleBarPress`).
  `tests/validate.py` fails a `"/click MannersPrompt` literal anywhere but
  Clicks.lua's `LEGACY_BODIES`.
- **Auras.** `C_UnitAuras` on every client; never `UnitBuff`/`UnitAura`.
- **Public text** (README's player sections, CHANGELOG, listings, toc Notes):
  no "untested" / "mock client" / "not tried in game" disclaimers.
  `tests/validate.py` checks the toc Notes. Listing files hold only the page
  text.
- **Listings** are pasted by the user from `.github/curseforge-summary.txt`,
  `curseforge-description.md`, `wago-description.md` and `gallery.md`:
  neither CurseForge nor Wago has an API for the page text (uploads only).
  The pictures' order, titles, descriptions and alt text are one list,
  `GALLERY` in `tools/make-screenshots.py`: `gallery.md`, `media/UPLOAD.md`
  and every page's alt text follow it, and every page opens on its first
  picture, the moment the addon is for (`tests/validate.py`, "the listings
  tell the moment first"; mutations in `tests/mutations/storefront.py`).
  The CurseForge opening (down to *What you see*), the README's (down to
  *Installing*) and Wago's page each name every headline feature in
  validate.py's `_HEADLINES` ("the listings name what ships"): a release
  whose highlight is new adds it there and to the three pages. The summary
  is one line of 150 characters at most.
- **Secrets.** Never take, type or store an API key. The user sets them with
  `gh secret set CF_API_KEY` (and `WAGO_API_TOKEN`), which prompts.
- **CPU.** Leave 2 cores free. With several agents running tests, split the
  workers between them (`--jobs`, `MANNERS_SCENARIO_JOBS`).
- **Parallel agents** work in git worktrees, never the live tree, and put new
  scenarios and mutations in files of their own. After merging, look for the
  same fix made twice (a chat line said twice, a mutation gone MISSED).
- **Files.** Write generated files with the Write tool, never bash heredocs
  (they eat backslashes; `scenarios.lua` is full of `\0`). Text is LF
  (`.gitattributes`); in Python write with `newline=''`. Lua is tab-indented,
  Python 4 spaces.
- Never hand-edit a generated toc or a version number: `tools/maketocs.py` and
  `tests/setversion.py` write them.

  SpellEffect, SpellLevels, SpellReagents, SpellMisc, SkillLineAbility,
  ItemSparse, ChrRaces, ... The builds cited in the code: Forever
  1.60.1.70790 (read at 1.60.1.70178 until hunt 34, and checked again against
  70450, 70532 and 70790), Classic Era 1.15.9.70003, TBC 2.5.6.69795, Mists
  5.5.4.70032, retail 12.1.0.69933. Forever's 1.60.1.70450 added three weapon
  items (`since` in `Buffs.lua`'s `ENHANCEMENTS`), changed Battle Shout's target
  from the caster's party (20) to the caster's raid (56, the radius unchanged),
  so Forever's set has no `partyIsSubgroup`, and renamed Salvation to
  "Salvation" and "Mass Salvation" (the audit takes either name). Build 1.60.1.70790 then deleted Salvation
  and Blessing of Light outright (ids 1038, 25895, 19977-19979, 25890), so
  Forever's paladin has Wisdom, Might and Kings only (`GONE` in `Buffs.lua`);
  Classic Era and Burning Crusade keep both, and the audit reads Forever at 70790. The audits
  read the build per client from this line.

  Forever database) for tooltips, levels and "Requires" lines.

  reader for it.
- **API and globals per client**: `Ketho/BlizzardInterfaceResources` (API
  dumps, GlobalStrings, CVars) per branch.
- **Addons known to work on Forever**: the installed ones under
  `D:\wow\World of Warcraft\_classic_beta_\Interface\AddOns` (EnhanceQoL,
  QuestieDB with its Camelot data, ...). Grep them when the API misbehaves.
- Never guess a client string (race file, CVar, class token): the Haranir's
  race file is `Harronir` (ChrRaces 86 and 91), and friendly nameplates are
  `nameplateShowFriendlyPlayers` on Forever and retail but
  `nameplateShowFriends` on Classic (`ns.FRIENDLY_PLATES_CVARS`).
