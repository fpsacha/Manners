# Manners -- guide for agents

Read this first. Not shipped (`.pkgmeta` ignores it). State and open items:
`STATUS.md`. Release checklist: `RELEASING.md`. What changed: `CHANGELOG.md`
(written for players). Test internals: `tests/README.md`. Tool details:
`tools/README.md`.

## What it is

A World of Warcraft addon (MIT, github.com/fpsacha/Manners, branch `master`,
CurseForge 1705364, Wago `rNkgzlNa`) that returns buffs. It notices who buffed
you, works out what you owe, and puts one secure button (the prompt) on screen;
a press targets them by name, casts, and hands your target back. It also offers
your group, people who ask in chat, and passers-by missing your buff, reminds
you of your own self-buffs, keeps a favour ledger, and can say a line when it
casts (fixed sets or the "In character" set). Addons cannot cast on their own:
everything except the keypress is decided in Lua and parked on the button.

Cross-file sharing: a local one file needs from another goes on `ns` where it
is defined; a later file copies it into a local at load, an earlier one (Core's
lifecycle) reads `ns.X` at call time.

Adding a setting: its default in `Core.lua`'s `defaults` (and repair in
`ns.ClampSettings`), its definition in `Options/<Tab>.lua`, its place in
`Options/Window/Layout.lua` (`tests/scenarios/layout.lua` requires every
control placed exactly once), and its strings translated.

## The five clients

| flavour key | client | interface | toc | family | combat log | secret values | UnitName 2nd return |
|---|---|---|---|---|---|---|---|
| `camelot` | WoW Forever 1.60.1 (a Midnight fork, vanilla content) | 16001 | `Manners_Camelot.toc` | modern | no | yes | surname |
| `vanilla` | Classic Era 1.15.9 | 11509 | `Manners_Vanilla.toc` | classic | yes | no | realm |
| `tbc` | Burning Crusade Classic Anniversary 2.5.6 | 20506 | `Manners_TBC.toc` | classic | yes | no | realm |
| `mists` | Mists of Pandaria Classic 5.5.4 | 50504 | `Manners_Mists.toc` | classic | yes | no | realm |
| `mainline` | retail Midnight 12.1.0 | 120100 | `Manners_Mainline.toc` | modern | no | yes | realm |

All five ship (Classic Era since 1.6.7, the rest since 1.7.0). Forever is the
default everywhere in the tests and the only client anybody here plays.

- **Flavour.lua** matches the interface number against bands tried in order
  (camelot first: 16001 and 11509 are both five digits). `WOW_PROJECT_ID` is a
  cross-check only (it is MAINLINE on Forever and retail alike). An unknown
  interface falls back to the project id's family, else `modern`.
- **Buffs.lua** has one set per flavour (`SETS`); an unrecognised flavour gets
  its family's (classic -> vanilla, modern -> mainline). The chosen set fills
  `ns.BUFFS`, `ns.OWN_BUFFS`, `ns.EXCLUSIVE_BUFFS`, `ns.CLASS_AUTO`,
  `ns.CLASSES_WITHOUT_BUFFS`, `ns.PARTY_IS_SUBGROUP`, `ns.GROUP_IS_RAID`,
  `ns.SHOUT_YARDS`, `ns.WIDE_CASTS`, `ns.GROUP_BY_CLASS`, `ns.FAVOUR_ONLY_IDS`,
  `ns.NOT_FAVOUR_IDS`, `ns.RANK_LEVEL`. Branch on those fields and the per-buff
  flags (`partyOnly`, `groupOnly`, `selfCast`, `alone`, `alike`, `neverAuto`,
  ... documented at the top of the file) rather than on flavour names. The
  camelot set is vanilla's (`__index`) with its own buffs, and is still called
  "vanilla" in `ns.BUFFS_SOURCE`; tbc builds on vanilla the same way.
- **Client-specific behaviour** (grep `ns.Flavour.flavour` / `.family`):
  - Forever only: surnames joined with a space (`caps.unitNameIsSurname`);
    the mage's scrolls (Familiar, Weapon imbue: `CAMELOT_OWN`, used with
    `/use item:<id>`); the Reagent Economy perk (`ns.ReagentWaived`);
    group casts reaching the whole party and raid (`groupIsRaid`); regional
    unique names in `/w` (Speech.lua asks the client, and assumes them on
    Forever when it will not say); no Blessing of Sanctuary, Omen of Clarity
    passive, Kings and Divine Spirit trained.
  - classic family (vanilla, tbc, mists): the combat log is read in addition
    to the aura scan (`ns.combatLogArmed`); never registered on modern clients
    (registration is refused there).
  - mists and mainline: a single buff on a group member lands party-wide
    (`wideCasts`), shouts reach 100 yards, their own `rankLevel`; mists' raid
    buff kinds do not stack (`alike`); mainline has no own-buff families and
    seven classes with nothing for others.
  - level cap for "Skip players below level": 60, tbc 70, mists and mainline 90
    (Core.lua).

## Checks

| Command | What | Time |
|---|---|---|
| `python tools/check.py` | validate, runharness, runscenarios (Forever); one summary line per step, non-zero on any failure | minutes |
| `python tools/check.py --flavours` | also each client's own scenario file as that client (era.lua as vanilla, tbc.lua, mists.lua, mainline.lua) and every `tests/scenarios/*-fixes.lua` as each client | longer |
| `python tools/check.py --anchors` | also `tests/selftest.py --anchors` | seconds more |
| `python tests/selftest.py --changed [REF]` | the mutations of the addon files that differ from REF (default master) | minutes |
| `python tests/selftest.py` | every mutation (about 2,400), each judged by the check it names | about 20-40 minutes; see the docstring |

`--jobs N` on check.py, runscenarios.py and selftest.py defaults to cores - 2.
Run the cheap checks while working, `--changed` before handing work back, and
the full selftest once, before a release.

`tests/runscenarios.py` flags: `--scenario NAME` and `--file FILE`
(`scenarios.lua` or a file in `tests/scenarios/`; both repeatable),
`--select pick.json`, `--jobs N`, `--flavour X` (the whole suite with X as
`Mock.reset()`'s client; same as `MANNERS_MOCK_FLAVOUR=X`), `--flavour X
--baseline` (prints only failures not in `tests/baselines/<X>.txt`, and
baseline entries that now pass; `--update-baseline` rewrites the file),
`--trace PATH` and `--shard I/K` (used by selftest). A run ends with
`failures: N`. Off Forever most reds are fixtures written for Forever (two-part
names, scrolls, secrets), which is what the baselines hold.

`tests/selftest.py` flags: `--anchors` (every mutation still finds its text),
`--changed [REF]`, `--plan` (which scenarios judge each mutation), `--whole`
(every mutation on the whole suite, slow), `--fresh-trace` (ignore the trace
kept in `%TEMP%/manners-selftest-trace`), `--jobs N`. A run fails on MISSED,
WRONG CHECK, ANCHOR GONE or NOT RESTORED.

Others: `tests/baseline.py` (a fingerprint of what Forever decides and arms:
diff it before and after a change made for another client), `tests/bughunt.py`
(known fault shapes; reports known false positives), `tools/lua51_limits.py`
(the tightest functions), `tools/perf_probe.py` and `tools/profile_scan.py`
(pcall counts, cost per scan), `tools/render_prompt.py`, `render_ledger.py`,
`render_options.py` (draw the UI from the mock; not pixel-true about light).

CI (`ci.yml`, every push): validate, runharness, runscenarios,
`selftest.py --anchors`, and the listing images drawn with `--strict`. The full
selftest does not fit a runner and is run locally.

Nothing here talks to a running client. For the game itself, ask the user to
run `/manners selftest` (a report to paste) or the `/manners dev` tools
(`clicks`, `try`, `look`, `forms`) and paste the output, or for a screenshot.

## Scenarios and mutations

- **Scenarios** are Lua run against the mock. `tests/scenarios.lua` is the old
  main file (do not append to it); new ones go in `tests/scenarios/<topic>.lua`,
  found by glob and run after the main file in name order. A file starts
  `local dir, H = ...` and takes helpers from `H` (`fail`, `load`, `drive`,
  `strangers`, `freshPrompt`, `pressButton`, `owe`, ...: the table near the end
  of `scenarios.lua`). Shape: `Mock.reset()`, set the mock
  (`Mock.setFlavour("mists")`, `Mock.class = "PRIEST"`, ...),
  `local ns = load(scenario)`; `nil` means "skip" (a narrowed run left it out);
  report with `fail(scenario, text)`. Put back every global you replace.
- **Names** start with the file's topic (`"flows-fix: vanilla: ..."`,
  `"era: ..."`) so a mutation can name exactly one.
- **Mutations** live in `tests/mutations/<topic>.py`, found by glob and run with
  `mutate()` in scope:
  `mutate(file, old, new, label, expect=..., script="runscenarios.py")`.
  `old` is exact code text (first occurrence is replaced; make it unique),
  `expect` is matched case-insensitively against the failing lines (usually a
  scenario name), `script` is the suite that must catch it (default
  `runharness.py`; `validate.py` for doc and structure checks). Every fix gets
  a scenario and a mutation that undoes the fix.
- **Anchors**: changing code or comments a mutation's `old` sits on means
  updating that mutation so it still applies the same fault;
  `python tests/selftest.py --anchors` must report every anchor live. Some
  anchors sit on `README.md` and `RELEASING.md` text (validate.py checks them).
- A scenario that cannot go red is worse than none: run the mutation and see it
  CAUGHT by the named check.

## Release

1. Notes under `## Unreleased` at the top of `CHANGELOG.md`, for players.
2. `python tests/selftest.py` in full, by hand (the release tool never runs it).
3. `python tools/release.py X.Y.Z` (`--dry-run` prints the steps). It checks
   master, a clean tree, the notes and `tools/check.py`; runs
   `tests/setversion.py`; commits "Manners X.Y.Z" with the Co-Authored-By line
   from `--coauthor` or `MANNERS_COAUTHOR`; pushes master and waits for CI;
   tags `vX.Y.Z` (annotated) and pushes it; waits for `release.yml`; prints
   the packager's "Game version:" line and the upload results.

Versions: `X.Y.Z`, `X.Y.Z-alpha.N`, `X.Y.Z-beta.N` only. Never edit a version
by hand: `tests/setversion.py` writes every toc, `ns.BUILD` in
`Prompt/Prompt.lua` and the changelog heading. The manual steps, and how to take
back a failed tag, are in `RELEASING.md`.

## Translations

Every player-facing string is `L["English text"]`, a literal (validate fails on
`L[variable]`). The key is the English; changing the English is a new key.
Validate fails on any locale missing a key or holding one the code no longer
asks for, so no new or changed string lands without all eight translations
(deDE esES frFR itIT koKR ptBR zhCN zhTW). No Russian, ever.

1. `python tools/locale_todo.py [--out DIR]`: `<code>.todo.json` per locale,
   each missing key mapped to `""`, and the counts.
2. Translate the values. Keep every `%s`, `{token}` and `|c...|r` as the English
   has them. Game terms -- spell, item, class, race and zone names, and the
   client's own UI words (nameplates, Key Bindings) -- use that client's
   official localized name (Wowhead in that language; GlobalStrings from
   Ketho/BlizzardInterfaceResources), never a free translation. Slash
   commands stay English.
3. `python tools/locale_add.py <code> <file.json> [...]` per locale: merges
   into `Locales/<code>.lua` without losing a line, checks with
   `tools/check_translation.py`, rebuilds with `tools/build_locale.py`.
4. `python tests/validate.py`.

`python tools/locale_keys.py --missing <code>` lists the gaps of one locale.

## In character phrases

`Phrases.lua` holds the pools; `RP.Pick` chooses one line at the click from the
pools that fit the moment. Pools: `RP.RACE.<family>.<kind>` (kinds `thanks`,
`asked`, `offer`, `group`, `kin`, and `night`/`morning`/`city`/`outsider`
where a people has them), `RP.FACTION`, `RP.GENERAL`, `RP.KIN`,
`RP.CLASS.<CLASS>.<kind>`, `RP.SPELL.<buff key>`, `RP.GIFT.<buff key>` (thanks
only; `{gift}` is the spell they gave you), `RP.TRADE`, `RP.HISTORY`,
`RP.PLACE`, `RP.TIME`, `RP.TARGET`, `RP.SAME.<CLASS>`, `RP.ONTO`.
`<family>` comes from `RP.FAMILY`, keyed by `UnitRace`'s second return.

- Add lines with `python tools/add_phrases.py pools.json`: a list of
  `{"pool": "RACE.<family>.<kind>" | "CLASS.<CLASS>.<kind>" | "SPELL.<key>" |
  "GIFT.<key>" | "SAME.<CLASS>", "lines": [...]}`. It appends to the pool (or
  creates it at the end of its table), escapes, and refuses what
  `tests/scenarios/rp.lua` would.
- The rules (`rp: the lines are short and safe in a macro`): at most 85
  characters with `{name}` -> "Bartholomewz" and `{buff}`/`{gift}` ->
  "Power Word: Fortitude"; no `|`, `[`, `]` or line break, no leading `/`; no
  line equal to another once reduced to its letters; only the `{name}`,
  `{buff}`, `{gift}` tokens, `{gift}` only in TRADE and GIFT; never the word
  "buff" (the set is in character); every pool at least two lines. A buff key
  only another client has goes in `rp.lua`'s `elsewhere` list.
- Each line is a player-facing string: all eight translations before it lands.
  On other languages an untranslated line is dropped at load.
- **Examples caveat**: the first lines of the pools are the phrase box's
  examples, and a player's saved box is recognised by matching them exactly.
  Never reword or reorder the first lines of a pool; append. A reworded
  example goes into `RP.LEGACY.reworded` as it read before. Giving a people
  its first pool changes its examples (as for the Haranir in 1.7.2).
- Race file names are the client's `ChrRaces.ClientFileString`, not the race's
  name: `Scourge` (Forsaken), `EarthenDwarf`, `Harronir` (the Haranir). 1.7.2's
  Haranir lines never played because the key was guessed. Look it up.

## Hard rules

- **Lua 5.1.** 60 upvalues per function, 200 active locals. `tests/validate.py`
  fails a function over 55 upvalues or 190 active locals, or a file whose main
  chunk keeps fewer than 10 locals free. Fix by putting helpers in a
  `do ... end` block or lifting closures to file level. Tests run on
  `lupa.lua51`; test Lua stays 5.1-clean too.
- **Secret values.** Anything branched on passes through `ns.plain()` (secret ->
  nil). No `pcall`/`ns.safecall` on busy paths (per unit, per event, per
  repaint): call directly after a `type()` check. `pcall` only for restricted
  aura reads, library code, calls handed a possibly secret value, API drift
  and setup; `ns.Guard` at event, timer and module boundaries. The policy is at
  the top of `Core.lua`'s secret-safe section; `tests/scenarios/perf-budget.lua`
  caps pcalls per scan (12 city, 30 raid). No file keeps its own copy of `pcall`.
- **Combat.** The secure button's attributes cannot change in combat: what is
  on the prompt when a fight starts stays until it ends.
- **Macro.** 255 characters (`ns.MACRO_LIMIT`); the spoken line gets what the
  cast lines leave (`ns.PhraseBudget`). A press on anybody, yourself included,
  is `/target <name>`, `/cast <spell>`, and `/targetlasttarget` when your
  target is handed back (`Prompt/Macro.lua`, `STRATEGIES`); a self-cast shout
  is a bare `/cast`, a scroll `/use item:<id>`. No `[@player]` or any
  `[@unit]` conditional: they do not resolve on Forever. Secure buttons
  register `"AnyDown"`.
- **Auras.** `C_UnitAuras` on every client; never `UnitBuff`/`UnitAura`.
- **Public text** (README's player sections, CHANGELOG, listings, toc Notes):
  no "untested" / "mock client" / "not tried in game" disclaimers.
  `tests/validate.py` checks the toc Notes. Listing files hold only the page
  text.
- **Listings** are pasted by the user from `.github/curseforge-summary.txt`,
  `curseforge-description.md`, `wago-description.md` and `gallery.md`:
  neither CurseForge nor Wago has an API for the page text (uploads only).
- **Secrets.** Never take, type or store an API key. The user sets them with
  `gh secret set CF_API_KEY` (and `WAGO_API_TOKEN`), which prompts.
- **CPU.** Leave 2 cores free. With several agents running tests, split the
  workers between them (`--jobs`, `MANNERS_SCENARIO_JOBS`).
- **Parallel agents** work in git worktrees, never the live tree, and put new
  scenarios and mutations in files of their own. After merging, look for the
  same fix made twice (a chat line said twice, a mutation gone MISSED).
- **Files.** Write generated files with the Write tool, never bash heredocs
  (they eat backslashes; `scenarios.lua` is full of `\0`). Text is LF
  (`.gitattributes`); in Python write with `newline=''`. Lua is tab-indented,
  Python 4 spaces.
- Never hand-edit a generated toc or a version number: `tools/maketocs.py` and
  `tests/setversion.py` write them.

## Data sources

- **Spell, item and race data**: wago.tools DB2 tables for the exact build
  (`https://wago.tools/db2/<Table>/csv?build=<build>`): SpellName, Spell,
  SpellEffect, SpellLevels, SpellReagents, SpellMisc, SkillLineAbility,
  ItemSparse, ChrRaces, ... The builds cited in the code: Forever
  1.60.1.70178, TBC 2.5.6.69795, Mists 5.5.4.70032, retail 12.1.0.69933.
- **Wowhead** per client (Classic, TBC Classic, MoP Classic, retail, and a
  Forever database) for tooltips, levels and "Requires" lines.
- **Blizzard's own UI code**: `Gethe/wow-ui-source`, one branch per client
  (`live`, `forever`, `classic` for Mists, `classic_anniversary` for TBC,
  `classic_era`, `ptr2`). Read how Blizzard's UI reads a thing before writing a
  reader for it.
- **API and globals per client**: `Ketho/BlizzardInterfaceResources` (API
  dumps, GlobalStrings, CVars) per branch.
- **Addons known to work on Forever**: the installed ones under
  `D:\wow\World of Warcraft\_classic_beta_\Interface\AddOns` (EnhanceQoL,
  QuestieDB with its Camelot data, ...). Grep them when the API misbehaves.
- Never guess a client string (race file, CVar, class token): the Haranir's
  race file is `Harronir` (ChrRaces 86 and 91), and friendly nameplates are
  `nameplateShowFriendlyPlayers` on Forever and retail but
  `nameplateShowFriends` on Classic (`ns.FRIENDLY_PLATES_CVARS`).
