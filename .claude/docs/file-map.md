# Manners -- the file map

Every file and folder of the repository, what lives in it, and how to add a
setting. Moved out of `CLAUDE.md`, word for word; `CLAUDE.md` is the index,
read first.

## File map

Load order is `Manners.toc`'s file list; every test loader reads it from there
(`tests/addonfiles.lua`). A new file goes into `Manners.toc`, then
`python tools/maketocs.py` rewrites the five generated tocs, which carry the
same list (`tests/validate.py` fails until they match).

| Path | What lives there |
|---|---|
| `Manners.toc` | the source toc: file list, Notes in nine languages, version. The only toc anybody edits |
| `Manners_<Flavour>.toc` | Camelot, Vanilla, TBC, Mists, Mainline: generated by `tools/maketocs.py` from `Manners.toc` (its whole body, file list included), each with its own `## Interface`; never hand-edit |

Cross-file sharing: a local one file needs from another goes on `ns` where it
is defined; a later file copies it into a local at load, an earlier one (Core's
lifecycle) reads `ns.X` at call time.

Adding a setting: its default in `Core.lua`'s `defaults` (and repair in
`ns.ClampSettings`), its definition in `Options/<Tab>.lua`, its place in
`Options/Window/Layout.lua` (`tests/scenarios/layout.lua` requires every
control placed exactly once), and its strings translated. A setting most
players of a class change also goes in the layout's `simple` list, or the
simple view leaves it out; one that belongs to a switch is indented under it
and named in `parents`, so search can say which switch to turn on. No page
is over about three screens with its folds shut (`menu.lua` holds each to
3.1): fold fine print rather than raise that.

Which page a new setting goes on is the subject it is about, never the file
it is written in: other people (*Who to buff*, *Who to skip*, *When to offer*),
your own buffs (*My own buffs*) and your pet (*My pet*, hunters), where and
when Manners stays quiet (*Quiet times*), a fight (*In a fight*), what you say
or ask (*What I say*), how it looks (*Look*). The page ids are `general`,
`who`, `skip`, `when`, `self`, `pet`, `quiet`, `fight`, `click`, `appearance`,
`profiles` and `diagnostics`. A section key starts with its page id and changes
when the section moves (`quiet.holdBack`); a setting key never changes. A
saved fold's open state follows a renamed section through `renamedFolds` in
the layout. A page added to the layout also goes in `layout.lua`'s `GROUPS`
(the sidebar's groups, in order) and in `window-classes.lua`'s `TABLE` (the
pages each class sees), and the page's fields in the reset lists in
`Options/Advanced.lua` (with `model-window.lua`'s EXPECTED, KEPT and HOOKS).

A control gets the gold changed mark, and a click that puts it back, when
`DefaultOf` (`WindowPage.lua`) finds its default: a control whose `get` is a
shared getter in `ns.OptionsPage.BOUND` (`Options/Shared.lua`), or a path with
a single `FIELDS` entry. A control with neither shows no mark; leave it out of
`BOUND` and say so in a comment rather than invent a default.

Text that points at a control (a chat line, a tooltip, a note) names its page
through `Page.TabOf(path)` or `Page.RefTo(label, path)` (`Options/Shared.lua`),
never a page name written by hand: the answer follows the layout and the
translation, so a control that moves takes its sentences with it. Files that
load before `Options/` (the root files, `Prompt/`) call `ns.TabName(path)`
(`Core.lua`) only when a line is said, never at load. A fight button's tooltip
ends with `ns.AddSettingsLine(tip, path)`. `menupass-pointers.lua` fails a page
named by hand.
